## Did Slice A demo?

**No — it is built and gated, not demoed.** The demo requires Gramps running on the owner's machine.
**[PR #82](https://github.com/randyjreid/gramps-live-api/pull/82)**, 4 commits, 23 files, +2,783 lines,
64 new tests, **1490 passed / 6 skipped**, guard 0 findings, lock files unchanged before and after.

**The demo to run** is in `docs/slice-a-demo.md`: start Gramps, then `/health` with a valid token → the
tree's name and person count · close the tree → clean *no tree open* · bad token → 401 · `Origin` header
→ 403.

**⭐ The real deliverable is the boundary, enforced by tests that name nothing.** Rule 1 parses
`accessor.py` for every top-level public `def` and requires each to refuse a non-main thread — **so the
fourth helper is covered by the act of writing it.** A third test guards that premise and **fired on its
own subject** (`Any` and `on_main_thread` were reachable and invisible to a `def` scan), fixed **with no
exemption list**, because an exemption for an obviously-harmless callable is the enumeration failure one
level up. Rule 2 is an AST walk refusing `.db` outside the accessor, **with its bound stated: it is
syntactic, and `getattr(dbstate, "db")` escapes it.**

**One dispute worth the owner's eye:** the Windows ACL on the token file **buys close to nothing against
R8's own threat model** — `%APPDATA%` already grants only the user, SYSTEM and Administrators, and R8's
accepted residual already concedes a process running as the owner. What it **costs** is a subprocess
spawn (`icacls`, since the AIO has no pywin32) **on Gramps' startup path**, which is where an AV scanner
intercepting process creation shows up. Implemented as ruled, capped at 10 s, non-fatal, achieved
protection logged as fact. **The builder would drop it; the conductor left it in place rather than
reverse a security control unilaterally.**
